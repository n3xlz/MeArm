# DevTools —— 开发过程中写的辅助程序

这里放的都是**开发工具**，不是提交给考核的功能代码。它们和主程序 `Task1235/` 完全独立，
可以单独编译、单独烧录，互不干扰。放在仓库里的目的是让「开发过程」可复核：
每个结论（摇杆中位值、取放姿态角度、标定公式对不对）是怎么测出来的，都能在这里找到工具。

| 目录 | 类型 | 干什么 |
| --- | --- | --- |
| `joy_cal/` | Arduino 草图 | **摇杆中位标定工具**：上电松手 3 秒自动记录四轴居中值，之后把四个方向推到底追踪极值，每 0.3 秒打印一次并当场自检（断线 / 某方向没推过 / 两侧不对称会直接标在行尾）。不需要舵机，不需要 Servo 库 |
| `TeachRecorder/` | Arduino 草图 | **示教记录器**：人工用摇杆把机械臂摆到目标姿态，按键记录并打印四轴角度，用于给任务二录取放点位 |
| `test_task5/` | PC 端测试台 | **任务五自动化测试**：把真实源码编译到电脑上跑，验证逆解边界、状态机、轨迹生成、曲线过点精度等 9 项（详见 `任务五测试报告_20261016.md`） |
| `Test/` | Arduino 草图 | **早期版本的整机草图**，任务一阶段用过的旧版，保留下来作为开发过程的留痕 |

## 为什么任务五要用 PC 端测试台

任务五的算法链路（正解 / 逆解 / 轨迹生成 / 状态机）在实物上验证的成本很高 ——
标定没做之前，任何目标点都会被判为「舵机行程不足」，看不到真正的问题。
于是搭了这个测试台：**把真实源码编译到电脑上运行**，用桩件替换掉三个外部依赖
（`Servo` / `Serial` / `millis()`），被测的仍然是源码本体。

它每次运行都从最新 `.ino` 重新生成，源码改一次就跟着重跑一次 ——
这样既能在没有实物的时段推进排查，也不会出现「文档里抄代码抄错常量」那类失真。

## 用法

三份 Arduino 草图直接用 Arduino IDE 打开对应的 `.ino` 即可（只依赖官方 `Servo` 库）。

测试台：

```bash
cd DevTools/test_task5
zsh build.sh
```

依赖 `arduino-cli`（Arduino IDE 2.x 内置）、Arduino AVR core、官方 `Servo` 库和 `g++`。
脚本里的路径都是相对本目录的，clone 到任何位置都能直接跑；
`arduino-cli` 不在默认路径时，用环境变量 `ARDUINO_CLI` 指定。

`gen/` 和 `build/` 是构建产物，已在 `.gitignore` 里排除。
